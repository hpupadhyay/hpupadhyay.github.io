Crenell

Verified professionals asking honest questions, and getting honest answers

Built - Pre-Release

About

Crenell is an invite-only professional network where someone in a real decision can ask the question they cannot ask anywhere else, because nobody - not the answerer, not the reader, not the app - ever learns who they were. The privacy promise is a property of the database schema rather than a line in a privacy policy: an anonymous post is structurally unable to carry a reference to the account that wrote it.

Two Planes, Never Joined

  • Identity plane (private) - credentials, case runs, scores, ratings, signature and the Crenell Index. Known to the system, invisible to other members.
  • Anonymous plane (public) - forum questions and answers, with no link to a member. None.
  • A database constraint makes an anonymous content row unable to reference a member, so a bug cannot create the link
  • Post mode is chosen at post time and can never be edited afterwards

Login Required, Anonymity Optional

  • Every route needs a signed-in account - no guest mode, no read-only tier, no public pages, no shareable links
  • Anonymous posting is a per-post choice by a logged-in member, not a special permission
  • Every member has an identical interface and identical privileges on day one, with no in-app privilege ladder
  • Scored case runs are always attributable, because an unattributable result means nothing

The Three Layers

  • The Parapet - case-based decision exercises with deterministic consequences, answer-free Council debate, spoiler-gated Vault, and the Crenell Index. Free.
  • The Forum - anonymous questions and anonymous answers. Unranked and unrated, so anonymity is free to use.
  • The Chamber - a verified professional's scheduled paid sitting. Invitation only, and never purchasable.

Disclosure Handshake

  • A questioner can ask an answer provider to verify their standing. The provider decides.
  • One request, one decision, three outcomes: accepted, declined, or ignored
  • Only the requester ever learns the result, one member at a time, by consent
  • A request can never contain a proposed or guessed identity, which would turn the feature into a confirmation oracle
  • Disclosure volume is never displayed, never ranked, and never enters the Index

Where Anonymity Actually Leaks

  • Posting named and anonymous about the same subject in the same room - a deliberate mode with a persistent indicator, plus a self-exposure warning before an anonymous post
  • Small populations - anonymity quorum is enforced structurally below a minimum room size
  • Cross-thread correlation - handles rotate per thread, so nothing correlates across the forum
  • Interaction fingerprints - no typing speed, no read receipts, no presence, no precise timestamps
  • Notification leakage - never a push notification that reveals who replied to a specific anonymous post

Content Protection

  • Android FLAG_SECURE on every window, so screenshots and the task-switcher thumbnail are blocked
  • No share sheet, no copy-link, no deep links, no web view anywhere in the client
  • Not discoverable by search, because no public or cacheable route exists at all
  • The honest limit is recorded in the product plan rather than hidden: this does not stop an external camera, a screen mirror, or a member who retells the conversation later

How It Is Built

  • Flutter client with a single auth gate and no named-route table, so no screen can bypass sign-in
  • Fastify server and Postgres, with a not-found handler that returns 401 so an unbuilt route fails closed
  • The scoring engine is deterministic and replayed byte-for-byte against golden fixtures, because a live model cannot adjudicate a score consistently
  • Guards are CI-enforced: plane-seam isolation, commercial/merit isolation, case arithmetic, and a check that each case teaches what it claims

Current Status

  • Phase 0 complete - schema, auth wall, content protection and the isolation guards are all in place
  • Phase 1 in progress - the deterministic case engine, with 157 server tests and 13 client tests passing
  • Still to build - the feed, the forum composer, the disclosure handshake, the Index computation and Chambers
  • Invite-only closed beta is the entry model; there is no open registration and no public marketing page
